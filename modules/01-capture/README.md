# 模块 01：采集层（Capture）

## 它是什么？

采集层负责把 HDMI 进入 RK3588 的画面一张一张"抓"出来，交给后面的 AI 处理。

## 它干什么？

板子的 HDMI 接收芯片（rk_hdmirx）把电脑画面变成 /dev/video0 这个"视频水龙头"。
采集层就是拧开这个水龙头，一帧一帧接水（画面）。

## 输入是什么？

- HDMI 信号（来自电脑显卡输出），板端设备：`/dev/video0`
- 画面格式：BGR3（BGR888 三通道，2560×1440）

## 输出是什么？

`FrameBuffer`（一帧原始画面）：
- 原始像素数据（BGR，每像素 3 字节）
- 画面宽高（如 2560×1440）
- 帧号、时间戳
- DMA 文件描述符（零拷贝用）

## 谁调用它？

- `CoreRuntime`（核心运行时）→ 启动时打开设备，运行时持续取帧
- `LatestFrame`（最新帧缓存）→ 所有 Worker 从这里拿最新画面

## 它不能干什么？

- 不能改变画面内容（不做任何图像处理）
- 不能选择目标、不能推理
- 不负责 HDMI 信号是否存在的判断（那是 HDMI RX 硬件的事）

## 修改它会影响什么？

- 改它 = 改画面从哪来、怎么来
- 影响采集帧率、画面格式、缓冲区数量
- 影响所有下游（RGA、推理、检测）
- **当前已验证链路禁止随意改动**（见 docs/验证/真实HDMI闭环验证.md）
