# 模块 02：图像处理层（Image / RGA / 预处理）

## 它是什么？

图像处理层负责把"巨大"的原始画面，变成 AI 模型认识的"小图"。

## 它干什么？

AI 模型不能直接看 2560×1440 的大画面（又大又慢），它只需要看画面中间的一小块。

1. **裁剪（ROI）**：从大画面中间裁出 500×500 的一块（默认配置）
2. **缩放**：把 500×500 缩小/放大到模型要求的尺寸（如 640×640 或 256×256）
3. **格式转换**：把 BGR 转成模型需要的格式/通道顺序
4. **零拷贝加速**：用 RGA 硬件（RK3588 自带的 2D 图像加速器）做这件事，不让 CPU 慢慢搬

## 输入是什么？

- `FrameBuffer`（采集层的一帧原始 BGR 画面）

## 输出是什么？

`PreprocessedFrame`（预处理后的帧）：
- 模型输入尺寸的像素数据（如 640×640×3）
- 数据直接可喂给 NPU（tensor_data）

## 谁调用它？

- `WorkerPool` 里的每个推理 Worker（取最新帧 → 预处理 → 推理）

## 它不能干什么？

- 不负责 AI 推理（那是模块 03 的事）
- 不负责识别目标（那是模块 04/05 的事）
- 不能凭空创造画面内容

## 修改它会影响什么？

- 影响喂给模型的是什么画面 → 直接影响检测结果
- 影响整体性能（RGA 快，CPU 慢）
- **颜色顺序（RGB/BGR）和归一化改错 = 模型"失明"**（见 docs/AI/模型输入格式.md 的教训）

## 关键文件

| 文件 | 作用 |
|---|---|
| `core/src/rga/RgaProcessor.cpp/.hpp` | RGA 硬件加速处理（裁剪+缩放+格式转换） |
| `core/src/rknn/Preprocess.cpp/.hpp` | 预处理统一入口（RGA 优先，CPU 兜底） |
