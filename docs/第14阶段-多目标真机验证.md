# 第14阶段：真实 HDMI+NPU 多目标选择/锁定/切换/丢失恢复验证

> 日期：2026-09-03
> 目的：以 YU 参考项目为基准，在真实 HDMI + NPU 链路下验证多目标选择、锁定、切换、丢失恢复。
> 原则：全部使用真实链路（PC 画面 → HDMI → RK3588 → yolo261n → DecodeNMS → TargetSelector），无合成数据。

## 一、验证环境

- PC 端：多目标动画（tkinter 全屏，street 全屏底图 + bus 460×460 实心叠加，bus 在中心 ROI 内左右往返 130px + 每 5s 消失 2s）
- 板端：RK3588 + yolo261n（640 FP16），TargetSelector 三层选择（track_lock→rect_lock→score）
- 采集：PidTrace 逐帧 CSV（2617 帧，40 秒）
- 安全：`output_enabled=false`、`injection_allowed=false`、final_command 全程 0

## 二、多目标检测

实时链路（GET_STATUS）检测到 **8 个目标**（person×4、car×3、bus×1），
构图验证（imgdetect，单图 GT）：street 全屏 11 检测、street+bus 4 检测。

## 三、目标选择与锁定（YU 对齐验证）

| 行为 | YU 基准 | 真机实测 | 结果 |
|---|---|---|---|
| 多目标并存选择 | FOV→class→conf→距离→priority→锁定 | 8 框中选中离中心最近 bus | ✅ |
| 目标锁定稳定 | 锁定后不横跳 | **target_id=1 全程锁定 2617 帧** | ✅ |
| 锁定目标移动跟随 | 锁定 track 持续更新位置 | target_x 1066~1299px 连续跟踪 | ✅ |
| 锁定延续（类别变化） | rect_lock 位置匹配延续同 id | bus(class=5) 消失 → person(class=0) 同 id=1 延续 | ✅ |

## 四、目标切换

- 实测发生 **1 次切换**：初始 person(id=1, x≈1343) → 中心 bus(id=2, x≈1296)
  （无锁定时的 score 层重选，符合 YU"锁定优先，无锁定时选最近"语义）
- 切换后 id=2 持续锁定，无横跳

## 五、丢失恢复

- bus 消失（每 5s 消失 2s）期间：**target_id 不丢失、不切换**
  - rect_lock 用位置匹配把锁定延续到 street 底图的 person（class 变化但 id 不变）
  - confidence 显著变化 51 次（反映检测内容变化），但锁定保持
- 大跳变（>50px）41 帧：bus 重新出现时锁定框位置更新，符合"锁定优先"语义
- 相邻帧跳变 avg 7.2px：检测框正常抖动范围

## 六、锁定平滑性

- target_x 连续跟踪，误差 error_x ∈ [-213.8, +19.5]（bus 在 ROI 内运动范围）
- 无丢失帧（target_lost=0）：锁定目标始终有检测支撑（bus 消失时 street 底图目标补位）

## 七、安全验证

- final_command 非零帧：**0**（注入关闭）
- output_enabled=false、injection_allowed=false 全程保持
- 无任何 HID 写入

## 八、结论

真实 HDMI+NPU 链路下，TargetSelector 多目标行为符合 YU 基准：
1. 多目标并存时正确选择（距离+priority 排序）
2. 锁定稳定（2617 帧不横跳）
3. 目标切换正确（无锁定时重选最近）
4. 丢失恢复正确（bus 消失后锁定延续同 id，不误切换）
5. 全程无真实鼠标输出

**未确认项**（标记未知，不脑补）：
- YU 的 priority 精确权重数值（本阶段默认关闭，两级列表实现）
- 真实游戏场景（人物移动/遮挡）下的锁定行为（当前用照片动画近似）
