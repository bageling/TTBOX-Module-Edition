# P-1 硬件负载报告：黄瓦 320 INT8 @ 240fps（ttbox2）

> **阶段**：P-1 系统级硬件负载采集（仅测试，未修改 A1-A6/模型）
> **日期**：2026-08-14
> **配置**：3 Worker / V4L2 8 buffers / 1080p239.76 锁定 / conf=0.55 / CPU+GPU+NPU+DDR 全锁频
> **核心结论**：240fps 下硬件利用率**健康且大量余量**。NPU 三核为唯一接近饱和的资源（AI 吞吐 239.6fps ≈ 输入源 239.76fps）；CPU 每核 <22%、GPU 0%、DDR 峰值 34%、温度 61°C，均远未饱和。瓶颈 = 输入源本身，而非任何硬件。

## 4. IRQ 负载与线程调度

- **NPU 三中断全部集中在 CPU0**（IRQ1/2/3 计数 100% 在 cpu0 列）——IRQ 集中，但 CPU0 利用率仅 21.6%，未造成瓶颈。
- **Worker 线程无 CPU 亲和性绑定**（A1-A6 未设置 sched_setaffinity），3 个 worker 线程在 8 核间**自由频繁迁移**（每线程出现在 7~8 个不同 CPU）。
- 主线程/capture 线程同样跨核迁移。
- **Worker 负载均衡性**：三 worker 处理帧数 2396/2396/2396 完全一致，无抢帧不均衡（skip 仅因认领时序，非不均衡）。

## 5. 硬件合理利用率与性能余量（240fps 下）

| 资源 | 当前占用 | 剩余余量 | 结论 |
|---|---|---|---|
| CPU（8 核） | 12.9% 总体，单核 <22% | ~87% | 大量余量，非瓶颈 |
| GPU | 0% | 100% | 未参与，非瓶颈 |
| NPU（3 核） | 接近饱和（吞吐已贴输入源） | 按理论 3×6.5ms=461fps，实际 239.6，仅用 ~52% | 有 ~2× 算力余量但已被输入源封顶 |
| DDR | 峰值 34% | ~66% | 余量充足，非瓶颈 |
| 温度 | 61°C | 距降频阈值 >20°C | 无热风险 |

## 6. 瓶颈判断

1. **当前唯一瓶颈 = 输入源 1080p239.76fps**。AI Pipeline 239.6fps 已贴住输入源，即使硬件全部空转也无法超过输入。
2. 链路内无瓶颈：buffer starvation 已消除（poll_timeout=0）、DDR/CPU/GPU 大量余量、Decode/NMS ~0.12ms、set_input 0.07ms（INT8 直喂）。
3. **性能上界**：当前 3W 达到输入上限；若输入源 >240fps（如 360/480），NPU 理论可再上探（单核 run 6.1ms → 3 核并行理论 ~440fps），但会先撞 DDR/CPU 余量。
4. **非瓶颈观察项**（潜在优化点，不影响当前 240fps）：NPU IRQ 集中 CPU0、worker 线程无绑核迁移。若未来输入源 >240fps 或延迟要求更严，可绑核（worker→独立 A76）+ 均衡 IRQ，降低调度抖动。
