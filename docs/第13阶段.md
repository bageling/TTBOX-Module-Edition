## 为什么这样设计

- **Detector 与 TargetSelector 分开**：Detector 只负责"画面里有什么"（Detection[]），
  不关心"打哪个"；换模型/换检测算法不影响目标选择。
- **Coordinate 单独存在**：所有坐标系换算（模型坐标 → 原图坐标 → 目标点）集中在一处，
  禁止各模块各算一遍。
- **Controller 与 Mouse 分开**：Controller 只计算 MouseCommand（纯数学），
  Mouse 才负责"写设备"；本阶段 Controller 产出命令即停止。
- **MouseCommand 不依赖 HID**：MouseCommand 只是 dx/dy 数据结构，
  不知道也不关心如何写入 /dev/hidg*。
- **Web 不能直接改 Core 内部状态**：只能通过 RuntimeConfig（内存快照）热更新参数。

## 深化：TargetSelector YU 对齐（priority 排序）

第13阶段深化：以 YU 参考项目行为为基准，补齐 TargetSelector 选择链路：

```
Detection → FOV过滤 → class过滤 → confidence过滤
  → 距离FOV中心排序 → priority → 目标锁定 → 目标切换
```

新增配置（`TargetSelectorConfig`，默认关闭，不影响旧行为）：

```cpp
bool priority_enabled;                 // 是否启用优先级
std::vector<int> priority_classes;     // 优先类别（优先级=1）
std::vector<int> priority_classes_high;// 高优先类别（优先级=2）
```

- 启用后排序：priority 高者优先，同 priority 按距离近者优先
- 未启用：完全保持原"距离最近优先"行为（兼容既有测试）
- 详见 `docs/YU参考行为映射.md`

## 深化：Target Lock 丢失宽限

- 锁定目标短时消失（空检测帧）→ 立即 invalid（**安全红线**，不允许旧坐标输出移动）
- track 在宽限内（lost_grace_ms=30）不删除 → 恢复检测后**同 target_id 延续**
- 超过宽限才放弃激活，重新选择
- 目标切换时 AimThread Reset PID/余数/预测状态
- 详见 `docs/YU参考行为映射.md`
