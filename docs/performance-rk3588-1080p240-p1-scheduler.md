# P-1 硬件调度优化报告：黄瓦 320 INT8 @ 1080p240（ttbox2）

> **阶段**：P-1 硬件调度优化（未修改 A1-A6 功能逻辑/模型，仅外部 taskset/IRQ affinity/监控）
> **日期**：2026-08-14
> **配置**：黄瓦 320×320 INT8 / 1080p239.76 / 8 V4L2 buffers / conf=0.55 / CPU(A55 1.8GHz+A76 2.352GHz)+GPU+NPU+DDR 全锁频 performance
> **核心结论**：**Worker 线程绑定 A76 大核是唯一有效优化**（1W +21.8%、2W +15.6%、3W E2E -8.8%、CPU -27%）。NPU IRQ 分散、NPU core_mask 调整均无收益。240fps 输入下 3W+绑大核达到最优（239.7fps 贴输入源上限）。

## 2. 关键发现

### 2.1 Worker 绑 A76 大核 = 唯一有效优化（主结论）

| 配置 | 不绑核 | 绑大核 | 提升 |
|---|---|---|---|
| 1W 吞吐 | 106.6 | 129.9 | **+21.8%** |
| 2W 吞吐 | 201.1 | 232.4 | **+15.6%** |
| 3W 吞吐 | 238.8 | 239.2 | 贴输入源上限（+0.2%） |
| 3W E2E | 9.23 ms | 8.65 ms | **-6.3%**（30s: 8.42ms，-8.8%） |
| 3W run | 6.04 ms | 5.67 ms | **-6.1%** |
| 3W RGA | 2.30 ms | 2.20 ms | -4.3% |
| 3W CPU% | 6.3% | 4.6% | **-27%** |

**机制**：A76 大核 2.352GHz vs A55 小核 1.8GHz。worker 的 CPU 侧工作（RGA im2d 提交/同步、rknn_run 调用开销、帧认领轮询）在大核显著加速——run 从 6.37→5.32ms（1W，-16%）、RGA 2.45→2.12ms。NPU 硬件算力不变，但 CPU 端开销被压缩。

### 2.2 NPU IRQ 分散：无收益

- B（绑核+IRQ默认）vs C（绑核+IRQ分散大核）：FPS/E2E 几乎一致（8.65 vs 8.68ms）。
- D（不绑核+IRQ分散）：E2E 9.53ms 反而最差。
- **NPU IRQ 集中 CPU0 未构成瓶颈**：CPU0 空闲余量 78%+，中断处理开销可忽略。

### 2.3 NPU core_mask：无影响

- J（单 context core_mask=7 三核）run 5.36ms ≈ G（AUTO 单核）5.32ms。
- 黄瓦 320 INT8 单次推理无法跨核切分（与 yolo 640 FP16 结论一致）。三核并行收益仅来自**多 Worker 多 context**（3W），与 core_mask 无关。

### 2.4 绑核后调度质量（K 组 sysmon 验证）

- **Worker 线程零迁移**：tid 94907/94908/94909 分别在 30s 内**仅出现在 cpu4/cpu5/cpu6**（vs 未绑核时每线程跨 7-8 个核）。
- 主线程/capture 线程仍自由调度（未绑，无影响）。
- 绑核后 CPU 分布更均衡：cpu0 18.7%（capture/系统+IRQ）、cpu1-3 10-11%、cpu4-6 9.7-10%（worker）、cpu7 5.2%，**每核余量 >80%**。
- 全程无降频（NPU/DDR/GPU 0 降频样本）、温度 61.9°C 稳定。

## 6. 最终推荐配置

| 项 | 推荐 | 依据 |
|---|---|---|
| Worker 数量 | **3** | 1W 130 / 2W 232 / 3W 239.7（贴输入源） |
| CPU affinity | **worker→cpu4,5,6（0x10,0x20,0x40）**，capture 可留小核或不动 | 1W +22%、2W +16%、E2E -9%、CPU -27%、零迁移 |
| NPU core_mask | **{1,2,4}（每 worker 独立核）** | core_mask=7 无收益（run 不变） |
| NPU IRQ affinity | **保持默认（ff）** | 分散无收益，IRQ 集中非瓶颈 |
| 调度策略 | CPU/GPU/NPU/DDR 全 performance+锁频；worker 实时优先级保持（已由 runtime 设 prio=1） | 0 降频、温度 61.9°C |
| V4L2 buffer | 8 | 消除 starvation（4→8 后 poll_timeout=0） |

**一句话**：当前 1080p240 输入下，**3 Worker + 绑 A76 大核 + 8 buffers + 全锁频**即最优（239.7fps 已封顶输入源）；若未来输入源 >240fps，绑大核带来的 1W/2W 吞吐增益（+16~22%）将直接转化为更高 Pipeline 上限。
