# 模型输入格式（yolo261n 关键修复记录）

> 本文档记录一个真实踩坑+修复过程。
> 这个坑曾经让 AI"睁眼瞎"：模型能加载、能推理，但就是检测不到任何东西。

---

## 背景：yolo261n 是什么？

`yolo261n-rk3588.rknn` 是一个 COCO 80 类通用检测模型：
- 输入：640×640 图像
- 数据类型：**FP16**（16 位半精度浮点）
- 输出：单输出 `[1, 84, 8400]`（8400 个候选框 × 84 个值）

## 历史问题：模型"失明"

### 现象

用 TTBOX 跑 yolo261n：
- ✅ 模型加载成功
- ✅ NPU 推理执行成功
- ❌ **检测结果永远为 0**

分析输出张量发现：
- 坐标通道（前 4 个）数值正常（中心 ≈ 320，符合 640 输入）
- **类别通道（后 80 个）全是 ~0**（sigmoid ≈ 0.502，即"什么都不确定"）

结论：**模型实际上看不到画面内容** —— 输入格式不对。

## 根因：FP16 模型被错误做了 /255 归一化

### 错误做法（修复前）

代码里对 FP16 模型做了这样的处理：

```cpp
// 把 0-255 的像素值除以 255，变成 0-1 的小数
// 再转成 FP16（16 位半精度浮点）
half_value = (pixel / 255.0f) → FP16
```

看起来"很标准"，但 yolo261n 模型实际要求的是：
**原始 0~255 像素值直接送入，由 RKNN runtime 自己处理量化。**

模型期望 UINT8 原始像素，却被喂了 FP16 归一化小数 → 特征全乱 → 类别通道全 0。

### 判定过程（实验证明）

用探针程序对同一张图喂 4 种输入格式：

| 输入格式 | 类别通道最大 sigmoid | 结果 |
|---|---|---|
| BGR + /255 归一化 FP16 | 0.502 | ❌ 失明 |
| RGB + /255 归一化 FP16 | 0.502 | ❌ 失明 |
| **BGR + 原始 0~255 UINT8** | **0.706** | ✅ 检测到 person |
| **RGB + 原始 0~255 UINT8** | **0.712** | ✅ 检测到 car |

结论明确：**必须喂原始 0~255 像素**。

## 修复：改了什么

修改了 3 处（都是最小改动，板端有 .bak 备份）：

### 1. `core/src/rknn/RKNNEngine.cpp` → `set_input()`

```cpp
// 修复前：只有 INT8 模型喂 UINT8 原始像素
if (info_.input_type == 2) {  // 仅 INT8
    in.type = RKNN_TENSOR_UINT8;
}

// 修复后：FP16 模型同样喂 UINT8 原始像素
if (info_.input_type == 2 || info_.input_type == 1) {  // INT8 / FP16
    in.type = RKNN_TENSOR_UINT8;
}
```

### 2. `core/src/rknn/Preprocess.cpp` → `finalize_tensor()`

```cpp
// 修复前：FP16 模型 → 转 half /255 归一化
// 修复后：FP16 模型直接透传原始 UINT8 像素（与 INT8 同路径）
if (input_type == 2 || input_type == 3 || !output->cpu_storage ||
    input_type == 1) {   // ← 新增 FP16 透传
    output->tensor_data = output->data;
    output->tensor_size = output->size;
    return;
}
```

### 3. `core/src/rknn/Preprocess.cpp` → `finalize_rga_tensor()`

同上：FP16 模型透传 RGA 输出的原始 BGR888，不做 half /255 归一化。

## 为什么这么改？

- **与 rknnlite 参考实现一致**：rknn 官方 lite 版就是喂 UINT8 原始像素
- **对 INT8/UINT8 模型零影响**：它们本来就是这条路
- **只影响 FP16 模型**：让它们也走"原始像素 → runtime 量化"的正确路径
- **不碰采集/解码/坐标/瞄准任何算法**：最小侵入

## 修复结果

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 检测数 | 0（失明） | **5（person/car/bus）** |
| 置信度 | — | 0.80~0.90 |
| 推理速度 | 不变 | 63.5ms（不受影响） |

## 教训（重要）

1. **不要假设模型输入格式**：FP16 模型不一定需要 /255 归一化
2. **"能加载、能推理" ≠ "能检测"**：输入格式错 = 模型白跑
3. **用探针实验定位**：对同一张图喂多种格式对比，一次就能确定正确格式
4. 改模型输入前，先看模型元数据（输入类型/尺寸/格式），再决定预处理方式
