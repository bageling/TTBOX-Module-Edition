# 模型系统

## 基础概念（小白必读）

### 什么是模型？

模型 = 一个"AI 大脑"的文件。
它是一堆经过训练得到的数字（权重），记录了"什么样的画面 → 是什么物体"的规律。
TTBOX 的模型是 `.rknn` 文件，放在板端 `/opt/ttbox/models/`。

### 什么是 RKNN？

RKNN = 瑞芯微（Rockchip）公司的 AI 模型格式。
普通模型（如 ONNX）在瑞芯微芯片上不能直接跑，必须先转换成 `.rknn` 格式。
TTBOX 用的就是这种格式，只能跑在 RK 系列芯片上（RK3588）。

### 什么是 NPU？

NPU = Neural Processing Unit，**专门负责人工智能计算的处理器**。
普通 CPU 算图像识别很慢，NPU 是专门为这种计算设计的，又快又省电。
RK3588 有 3 个 NPU 核，TTBOX 用 3 个 Worker 同时推理（并行加速）。

### 什么是输入尺寸？

模型只能"看"固定大小的图片：
- yolo261n 看 640×640
- jwdl_sjzv11 看 256×256

系统会把大画面裁剪缩放成模型能看的大小再喂进去。
输入越大，看得越清楚，但算得越慢。

### 什么是 INT8 / FP16？

这是数据的"精度/表示方式"：
- **INT8**：每个数值用 8 位整数表示（省空间、速度快、精度略低）
- **FP16**：每个数值用 16 位浮点表示（精度更高、稍慢）

模型声明什么输入类型，就要按对应的方式喂数据（这个坑见 `docs/AI/模型输入格式.md`）。

### 什么是 COCO？

COCO 是一个公开的物体识别数据集/标准，定义了 **80 个常见物体类别**：
人、自行车、汽车、摩托车、飞机、公交车、火车、卡车、船、
交通灯、猫、狗、椅子、桌子、手机、电脑、杯子……等等。

"COCO 80 类模型" = 能识别这 80 种常见物体的通用模型。

### 什么是类别（class）？

类别 = 物体种类，用数字编号表示：
- class 0 = person（人）
- class 2 = car（汽车）
- class 5 = bus（公交车）

### 什么是 Detection（检测结果）？

Detection = 模型对画面的一次"发现"：
- 发现了一个目标
- 知道它的类别（class_id）
- 有多大的把握（置信度 score）
- 它在画面的哪个位置（bbox 坐标 x1,y1,x2,y2）

### 什么是置信度（confidence）？

置信度 = 模型对自己判断的把握程度，0~1：
- 0.95：非常有把握是目标
- 0.50：一半一半（可疑）
- 0.10：基本不像

系统用阈值（conf）过滤：置信度低于阈值的检测直接丢弃。
TTBOX 默认 conf=0.55（jwdl）或 0.30（yolo261n 测试时）。

### 什么是 NMS？

NMS = Non-Maximum Suppression（**非极大值抑制**）。
同一个目标，模型可能框了它好几次（好几个重叠的框）。
NMS 的作用：多个重叠的框只保留"最好的那个"，去掉重复。
所以最终每个目标只有一个框。

## 当前模型清单

| 模型 | 输入尺寸 | 类型 | 输出结构 | 类别 | 特点 |
|---|---|---|---|---|---|
| **yolo261n-rk3588** | 640×640 | FP16 | 单输出 [1,84,8400] | COCO 80 类 | **通用模型**：识别人/车/公交车等日常物体；能力强但慢（43 FPS） |
| **jwdl_sjzv11** | 256×256 | INT8 | 6 输出 DFL-dist | 7 类 | **游戏专用模型**：识别特定游戏角色；极快（142 FPS） |
| sjzv11 / sjz_XCSH | 256×256 | INT8 | 6 输出 DFL-dist | 7 类 | 游戏专用变体 |
| sjzv8-v11-256int | 256×256 | INT8 | 单输出 [1,11,1344] | 11 类 | 游戏专用变体 |

## 哪个模型怎么选？

| 需求 | 选哪个 | 理由 |
|---|---|---|
| 识别通用物体（人/车/日常） | yolo261n | COCO 80 类 |
| 追求最快速度 | jwdl_sjzv11 | 142 FPS |
| 游戏特定角色 | jwdl_sjzv11 / sjz 系列 | 专用训练 |

**权衡**：模型越大/输入越大 → 能力越强、速度越慢。
yolo261n（640 输入）比 jwdl（256 输入）慢约 8.6 倍，但能识别的物体多得多。

## 模型放哪？怎么换？

- 板端位置：`/opt/ttbox/models/`（installed=已装 / staging=暂存 / registry=注册表）
- 切换方法：
  1. 修改 `config/default.json` 的 `model_path` 指向模型文件
  2. 修改 `model_input_width/height` 匹配模型输入
  3. 重启 ttbox-core 服务

⚠ **注意**：`model_path` 必须显式指定（默认会指向旧的 jwdl 模型路径）。

## 模型管理 API

Web 提供模型管理接口（`plugins/model/` + `scripts/ttbox_web.py`）：
- 列出所有模型
- 上传/暂存新模型
- 校验模型
- 安装/激活模型
- 移除模型

激活新模型后需重启 AI 流水线才生效（当前无热加载）。
