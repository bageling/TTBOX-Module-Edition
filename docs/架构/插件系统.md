# 插件系统

## 插件是什么？

插件 = 一个可以"插上/拔下"的功能单元。

TTBOX 把很多功能做成插件：
- Web 控制台（web）
- 画面预览（preview）
- 模型管理（model）
- 风扇控制（fan）
- WiFi 管理（wifi）
- 网络信息（network）
- 系统监控（monitor）
- 日志（log）
- 系统信息（system）
- 升级（upgrade）

好处：需要哪个装哪个，互不干扰，坏一个不影响其他。

## 插件的结构

每个插件是一个目录，包含：

```
plugins/web/
├── plugin.json         # 插件声明（名字/版本/入口/能力）
├── __init__.py
├── framework_api.py    # 插件实现（框架 API）
```

### plugin.json 长什么样？

```json
{
  "name": "web",
  "version": "1.0.0",
  "entry": "plugin_entry.py",
  "description": "Web 控制台"
}
```

### 插件入口长什么样？

```python
def register(context):
    """插件被加载时调用，向系统注册自己的能力"""
    ...
```

## 插件管理器（framework/plugin_manager/）

| 文件 | 作用 |
|---|---|
| `discovery.py` | 发现插件（扫描 plugins/ 目录） |
| `manager.py` | 插件管理器（加载/卸载/查询） |
| `lifecycle.py` | 生命周期（启用/禁用状态） |
| `integrity.py` | 完整性校验（文件是否齐全） |
| `install.py` | 安装 |
| `registry.py` | 注册表 |
| `repository.py` | 插件仓库 |
| `standard.py` | 插件标准/规范 |
| `transaction.py` | 事务（安装/卸载原子性） |
| `models.py` | 数据模型 |

## 插件如何工作？

```
系统启动
  ↓
framework 扫描 plugins/ 目录
  ↓
读取每个插件的 plugin.json
  ↓
调用插件入口的 register()
  ↓
插件注册自己的能力（Web 路由、预览、模型操作...）
  ↓
用户通过 Web 页面使用这些能力
```

## 如何新增一个插件？

1. 在 `plugins/` 下新建目录（如 `plugins/myplugin/`）
2. 写 `plugin.json`（声明）
3. 写 `plugin_entry.py`（实现 register()）
4. 重启 Web 服务，插件自动被发现

详细步骤见 `docs/开发/修改指南.md` 的"我要增加插件"章节。

## 安全说明

- 插件是系统的一部分，**只运行可信插件**
- 插件管理器有完整性校验，防止半成品插件破坏系统
- 安装/卸载是事务性的：失败自动回滚
