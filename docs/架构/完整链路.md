# 完整链路（从电脑画面到鼠标指令）

这是 TTBOX 最核心的一张图：**一帧画面从电脑屏幕出发，走完整个系统，变成控制指令的完整旅程**。

## 中文流程图

```
┌────────────────────────────────────────────────────────────────┐
│                       电脑（Windows PC）                        │
│                                                                │
│  PC主屏（2560×1440）                                            │
│    ↓                                                           │
│  GameViewer虚拟显示（EDID 虚拟显示器，让系统以为有第二块屏）       │
│    ↓                                                           │
│  显卡 HDMI 输出                                                  │
└───────────────────────────┬────────────────────────────────────┘
                            │ HDMI 线（只传画面，速度极快）
┌───────────────────────────▼────────────────────────────────────┐
│                   RK3588 AI 盒子（OrangePi）                    │
│                                                                │
│  ① RK3588 HDMI RX（hdmirx 硬件接收）                            │
│    ↓                                                           │
│  ② rk_hdmirx（内核驱动）                                        │
│    ↓                                                           │
│  ③ /dev/video0（V4L2 视频设备 = "画面水龙头"）                   │
│    ↓                                                           │
│  ④ TTBOX Capture（V4L2Capture 采集线程，141 FPS 抓帧）          │
│    ↓                                                           │
│  ⑤ RGA 图像处理（硬件加速：中心裁 500×500 → 缩放到模型尺寸）      │
│    ↓                                                           │
│  ⑥ AI 模型（yolo261n 等 .rknn 模型）                            │
│    ↓                                                           │
│  ⑦ RKNN NPU（神经网络处理器，3 核并行推理，43 FPS）              │
│    ↓                                                           │
│  ⑧ 模型解码（DecodeNMS：数字 → 检测框，映射回原图坐标）           │
│    ↓                                                           │
│  ⑨ Detection 检测结果（class_id + 置信度 + bbox 坐标）           │
│    ↓                                                           │
│  ⑩ TargetSelector 目标选择（多个目标 → 选一个）                  │
│    ↓                                                           │
│  ⑪ Coordinate 坐标转换（目标位置 → 与屏幕中心的偏差）             │
│    ↓                                                           │
│  ⑫ Mouse/HID 输出（把偏差转成鼠标移动指令，经 USB 注入）          │
│    ⚠ 当前 output_enabled=false：这一步被安全开关锁住            │
└────────────────────────────────────────────────────────────────┘
```

## 每步详解

| 步骤 | 名字 | 干什么 | 真实数据 |
|---|---|---|---|
| ① | HDMI RX | 硬件接收 HDMI 信号 | 2560×1440@144Hz 锁定 |
| ② | rk_hdmirx | 内核驱动，暴露视频设备 | /dev/video0 |
| ③ | /dev/video0 | V4L2 设备节点 | BGR3 格式 2560×1440 |
| ④ | Capture | 抓帧线程 | 141~142 FPS |
| ⑤ | RGA | 硬件缩放裁剪 | 500×500 ROI → 640×640 |
| ⑥ | AI 模型 | 图像 → 特征 | yolo261n-rk3588 |
| ⑦ | RKNN NPU | 神经网络计算 | 63.5 ms/帧（3 Worker 并行 43 FPS）|
| ⑧ | DecodeNMS | 解码 + 去重 + 坐标映射 | 5.4 ms |
| ⑨ | Detection | 结构化检测结果 | class/conf/bbox |
| ⑩ | TargetSelector | 选目标 | 最近中心/按类别 |
| ⑪ | Coordinate | 算偏差 | error_x/error_y |
| ⑫ | Mouse/HID | 注入鼠标 | ⛔ 关闭中 |

## 一帧的完整旅程（时间线）

一帧画面从 HDMI 进来，到检测完成，**全程约 66 毫秒**（端到端延迟）：

```
t=0ms    画面到达 HDMI RX
t≈0ms    V4L2 抓到帧（141 FPS，约每 7ms 一帧）
t≈0ms    RGA 裁剪缩放（硬件加速，<1ms）
t≈1ms    送入 NPU 开始推理
t≈64ms   NPU 推理完成（63.5ms，640×640 模型）
t≈65ms   DecodeNMS 解码完成（5.4ms）
t≈66ms   Detection 结果可用 → 交给目标选择
```

> 说明：66ms 是 yolo261n（640×640 COCO 通用模型）的端到端延迟。
> 如果用轻量模型（jwdl 256×256），推理只要 7.3ms，端到端约 8.4ms。

## 一条重要概念：为什么有两个"帧率"？

- **Capture 141 FPS**：采集线程抓到 141 帧/秒（画面快）
- **Inference 43 FPS**：AI 每秒只能分析 43 帧（推理慢于采集）

采集永远比推理快（好设计！）：系统总是拿着"最新的一帧"去分析，
不会因为 AI 慢而漏掉新画面。这就是"最新帧缓存（LatestFrame）"的作用：
AI 分析旧帧的同时，新帧不断进来，AI 一闲下来就拿最新帧，绝不分析过期画面。
