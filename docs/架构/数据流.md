# 数据流

本文档说明 TTBOX 里"数据"是怎么流动的：从一帧画面到一条控制指令，数据在每个环节长什么样。

## 一、图像数据流（实时链路）

```
┌────────────┐   BGR3 原始像素   ┌────────────┐
│ V4L2Capture │ ───────────────▶ │ FrameBuffer │
└────────────┘  2560×1440×3     └────────────┘
                                      │ LatestFrame（最新帧缓存，永远最新）
                                      ▼
                               ┌────────────┐
                               │ RGA/Preprocess │  裁剪 500×500 → 缩放
                               └────────────┘
                                      │ tensor_data（640×640×3 或 256×256×3）
                                      ▼
                               ┌────────────┐
                               │ RKNNEngine │  NPU 推理
                               └────────────┘
                                      │ raw_outputs（模型原始数字输出）
                                      ▼
                               ┌────────────┐
                               │ DecodeNMS  │  解码 + 过滤 + NMS + 坐标映射
                               └────────────┘
                                      │ Detection[]（检测框，原图坐标）
                                      ▼
                               ┌────────────┐
                               │ AimTargetMailbox │ 跨线程传给瞄准线程
                               └────────────┘
```

## 二、数据在每个环节的样子

| 环节 | 数据形式 | 示例 |
|---|---|---|
| 采集后 | BGR 像素数组 | `[0xB8,0x63,0x52, ...]` 11059200 字节 |
| 预处理后 | 模型输入张量 | 640×640×3 = 1228800 字节 |
| NPU 输出 | 原始张量 | yolo261n: [1,84,8400] 浮点 |
| 解码后 | Detection 列表 | `class=2 score=0.90 box=[1305,746,1383,801]` |
| 选择后 | 目标 | `class=5 center=(1238,744)` |
| 坐标后 | 偏差 | `error_x=-43 error_y=13` |
| 控制后 | 鼠标指令 | `dx=0 dy=0`（当前关闭） |

## 三、控制数据流（瞄准链路）

```
Detection[] ──▶ TargetSelector（选一个）──▶ 目标(位置)
                                                  │
                                                  ▼
                                       CoordinateTransform（算偏差）
                                                  │
                                                  ▼
                                       AimThread + PID（算移动量）
                                                  │
                                                  ▼
                                       MouseCommand(dx, dy)
                                                  │
                                                  ▼
                                       OutputBackend → HID
                                                  │
                                        ⛔ output_enabled=false（当前锁住）
```

## 四、配置数据流

```
config/default.json（文件）
      │ 启动时加载
      ▼
ConfigManager ──▶ RuntimeConfig（内存中的唯一真源）
      │                │
      │                ├──▶ Capture（采集参数）
      │                ├──▶ Preprocess（ROI/颜色）
      │                ├──▶ RKNNEngine（模型路径）
      │                ├──▶ DecodeNMS（conf/iou）
      │                ├──▶ AimThread（PID/热键）
      │                └──▶ OutputBackend（output_enabled）
      │
      │ IPC 热更新（Web 修改配置）
      ▼
RuntimeProfile ──▶ 各模块运行时参数（不用重启就生效）
```

## 五、状态数据流（给 Web 看）

```
各模块指标（帧率/延迟/检测数/注入状态）
      │ 持续采集
      ▼
CoreRuntime::collect_metrics
      │ GET_STATUS 请求
      ▼
IpcServer（/tmp/ttbox_core.sock）
      │
      ▼
Web 服务（scripts/ttbox_web.py）──▶ 浏览器页面显示
```

## 六、关键设计：为什么用"最新帧"而不是"队列"？

采集 141 FPS、推理 43 FPS，推理比采集慢。

- ❌ 如果排队：队列会越来越长，延迟越来越大，画面越来越旧
- ✅ 最新帧缓存：Worker 总是拿"当前最新"的一帧分析，旧的直接丢弃

效果：AI 永远处理最新画面，端到端延迟稳定（约 66ms），不会堆积。
