# 08 - 插件是什么？

## 一句话

插件 = 可以随时"插上/拔下"的小功能模块。
TTBOX 把很多功能做成了插件，需要哪个装哪个。

## 打个比方

插件就像手机 App：
- 手机出厂只有基础功能
- 想拍照 → 装个相机 App（插件）
- 想导航 → 装个地图 App（插件）
- 不想要的 → 卸掉，不影响其他功能

TTBOX 的插件也是一样：每个插件负责一项独立功能。

## TTBOX 有哪些插件？

| 插件 | 干什么 |
|---|---|
| web | Web 控制台（浏览器管理盒子） |
| preview | 画面预览（实时看盒子看到的画面） |
| model | 模型管理（上传/切换模型） |
| fan | 风扇控制 |
| wifi | WiFi 管理 |
| network | 网络信息 |
| monitor | 系统监控 |
| log | 日志查看 |
| system | 系统信息 |
| upgrade | 系统升级 |

## 一个插件长什么样？

```
plugins/web/
├── plugin.json         # 插件"身份证"（名字/版本/入口）
├── __init__.py
└── framework_api.py    # 插件的实际代码
```

`plugin.json` 内容：

```json
{
  "name": "web",
  "version": "1.0.0",
  "entry": "plugin_entry.py",
  "description": "Web 控制台"
}
```

`plugin_entry.py` 内容：

```python
def register(context):
    """系统加载插件时调用，插件在这里注册自己的能力"""
    # 例如：注册一个 Web 路由
    context.register_route("/api/web/status", handle_status)
```

## 插件怎么被系统发现和加载？

```
系统启动
  ↓
框架扫描 plugins/ 目录
  ↓
读取每个插件的 plugin.json（认身份）
  ↓
调用 register()（插件自我注册）
  ↓
插件能力可用（Web 页面/预览/模型管理...）
```

## 插件管理器负责什么？

`framework/plugin_manager/` 是插件的"管家"：

| 能力 | 说明 |
|---|---|
| 发现 | 找到 plugins/ 下所有插件 |
| 加载 | 读取声明、执行入口 |
| 生命周期 | 启用/禁用/卸载 |
| 完整性 | 检查插件文件是否齐全 |
| 事务 | 安装/卸载要么全成功、要么全回滚 |
| 安全 | 只运行可信插件 |

## 为什么用插件？

1. **解耦**：各功能互不影响，一个插件坏了不影响系统
2. **按需**：不用风扇控制就不装 fan 插件，省资源
3. **好扩展**：加新功能 = 加一个新插件目录，不动核心
4. **好维护**：每个插件小而独立，好读好改

## 我要加一个插件怎么做？

简单版（详细见 docs/开发/修改指南.md）：
1. 建目录 `plugins/我的插件/`
2. 写 `plugin.json`
3. 写 `plugin_entry.py`（实现 register）
4. 重启 Web 服务 → 自动发现
