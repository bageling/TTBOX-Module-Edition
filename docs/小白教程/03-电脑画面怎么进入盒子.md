# 03 - 电脑画面怎么进入盒子？

## 视频链路（眼睛）

电脑画面进入盒子的完整路径：

```
电脑主屏（2560×1440）
   ↓
虚拟显示器（GameViewer Virtual Display Adapter）
   ↓
显卡 HDMI 输出
   ↓ ═══════════ HDMI 线（一根高清视频线）═══════════
RK3588 HDMI RX（盒子上的 HDMI 接收口）
   ↓
rk_hdmirx（内核驱动，把信号变成视频设备）
   ↓
/dev/video0（视频设备 = "画面水龙头"）
   ↓
TTBOX Capture（拧开水龙头，一帧一帧接水）
```

## 一步步解释

### 1. 电脑主屏
电脑屏幕上显示什么，盒子就能看到什么。

### 2. 虚拟显示器（GameViewer）
电脑本来只有一块屏幕。为了给盒子提供画面，装了一个"虚拟显示器"驱动：
它让系统以为还有第二块屏幕（2560×1440@144Hz），
这块"虚拟屏幕"的内容会通过显卡 HDMI 口真实输出。

> 简单说：虚拟显示器 = 系统多了一块"看不见摸不着"的屏幕，
> 它的画面从 HDMI 口流出去。

### 3. HDMI 线
一根高清视频线，把画面从电脑显卡送到盒子。
**HDMI 只传画面，不传其他东西。**

### 4. HDMI RX（接收口）
盒子上的 HDMI 接收硬件，把电信号变成图像数据。
RK3588 支持 4K 输入，当前锁定 2560×1440@144Hz。

### 5. rk_hdmirx（驱动）
内核驱动，把接收到的画面暴露成 Linux 标准的视频设备 `/dev/video0`。

### 6. /dev/video0
Linux 里"视频设备"的接口文件。程序通过它读取画面帧。
格式：BGR3（三通道 8 位），2560×1440。

### 7. TTBOX Capture
采集线程，不断从 /dev/video0 抓帧，每秒 141 帧。

## 怎么验证画面真的进来了？

测试脚本（PC 端执行）：

```bash
# 全屏显示纯色（验证信号通没通）
python core/tests/fullscreen_solid.py "#00ff00" 30

# 全屏显示文字（验证画面内容正确）
python core/tests/fullscreen_text.py 30

# 全屏显示动画（验证是实时的，不是静态图）
python core/tests/fullscreen_anim.py 30

# 全屏显示一张图片（验证 AI 检测用的目标画面）
python core/tests/fullscreen_image.py 目标图.png 120
```

板端抓帧验证：

```bash
# 先停服务（它独占视频设备）
systemctl stop ttbox-core.service
# 抓 2 帧原始画面
v4l2-ctl -d /dev/video0 --stream-mmap --stream-count=2 --stream-to=/tmp/frame.raw
# 立刻恢复服务
systemctl start ttbox-core.service
```

把 raw 文件下载到电脑，对比颜色/内容即可确认链路畅通。

## 常见问题

| 问题 | 原因 | 解决 |
|---|---|---|
| 抓不到帧（busy） | ttbox-core 占着设备 | 先停服务再抓 |
| 画面全黑 | 信号没锁定 | 检查 HDMI 线/虚拟显示器 |
| 分辨率不对 | EDID 配置问题 | `hdmirx_edid --status` 查看 |

## 重要概念：USB 不是视频链路！

有人以为画面是通过 USB 进盒子的——**错**。

- **HDMI**：画面从电脑进盒子（眼睛）
- **USB**：指令从盒子出到电脑（手）

盒子"看"画面只走 HDMI。USB 是盒子与电脑之间的独立连接
（盒子伪装成鼠标键盘来"操作"电脑），和画面传输完全无关。
