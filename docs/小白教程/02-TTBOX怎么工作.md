# 02 - TTBOX 怎么工作？

## 一张图看懂工作流程

```
电脑画面 ──HDMI──▶ 盒子"看"到画面
                    │
                    ▼
            拆成一帧一帧的图片（每秒 141 张）
                    │
                    ▼
            图片缩小成 AI 能看的大小（640×640）
                    │
                    ▼
            AI 大脑（NPU）分析：画面里有什么？
                    │
                    ▼
            变成检测结果：类别 + 置信度 + 位置框
                    │
                    ▼
            从多个目标里选一个（打哪个？）
                    │
                    ▼
            算出目标偏离屏幕中心多少（偏差）
                    │
                    ▼
            算出鼠标该动多少（控制指令）
                    │
                    ▼
            通过 USB 把指令发给电脑（⚠ 当前关闭）
```

## 每一步在干什么？（人话版）

### 1. 看画面（采集）
盒子每秒钟从 HDMI 线"抓"141 张画面。
画面很大（2560×1440），像一张巨大的照片。

### 2. 缩小图片（预处理）
AI 模型看不了这么大的图，系统把画面中间裁剪出一块（500×500），
再缩放到模型需要的大小（比如 640×640）。
这一步用 RGA（硬件加速器）做，特别快。

### 3. AI 分析（推理）
缩小的图片送进 NPU（AI 专用处理器），
模型在里面算一遍：这张图里有哪些目标？分别是什么？
yolo261n 模型每张图要算 63 毫秒。

### 4. 变出检测框（解码）
AI 输出的是一堆数字，人看不懂。
解码器把它翻译成检测框：`类别=汽车，置信度=0.90，位置=(1305,746)-(1383,801)`。
同一个目标可能会框好几次，NMS 去掉重复的，只留最好的。

### 5. 选目标（选择）
画面里可能同时有好几个目标（3 辆车、1 个人、1 辆公交）。
选择器按规则挑一个（例如离屏幕中心最近的）。

### 6. 算偏差（坐标）
目标在屏幕的右下角，屏幕中心在哪？
算出目标离中心偏了多少像素（比如 偏右 43 像素、偏上 13 像素）。

### 7. 算移动量（控制）
偏差 → PID 控制器 → 平滑的鼠标移动指令（dx, dy）。
PID 保证移动平滑不抖动，不会"瞬移"。

### 8. 发送指令（输出，当前关闭）
把移动指令通过 USB 伪装成鼠标发给电脑。
**当前 output_enabled=false，这一步是锁住的，盒子只"看"不"动"。**

## 三个重要数字（实测）

| 数字 | 含义 |
|---|---|
| 141 FPS | 盒子每秒抓 141 帧画面 |
| 43 FPS | AI 每秒分析 43 帧（yolo261n 模型） |
| 66 毫秒 | 一帧从进来到检测完，全程耗时 |

## 两个"手"和"眼"别搞混

- **HDMI（眼睛）**：电脑 → 盒子，传画面
- **USB（手）**：盒子 → 电脑，传鼠标指令（当前关闭）

两条线各干各的！USB 不是视频线。
