# 07 - 坐标是怎么计算的？

## 目标：算出"目标偏离屏幕中心多少"

AI 找到了目标（检测框），接下来要回答一个问题：
**目标在屏幕中心的哪个方向？偏了多少？**

这个"偏差"就是坐标层（CoordinateTransform）算出来的。

## 三步计算

### 第一步：找目标中心

检测框给了左上角 (x1,y1) 和右下角 (x2,y2)，中心点就是：

```
中心x = (x1 + x2) / 2
中心y = (y1 + y2) / 2
```

例：框 (1196,706)-(1280,783) → 中心 = (1238, 744)

### 第二步：算与屏幕中心的偏差

屏幕中心（参考点）= (1280, 720)（2560×1440 画面的正中间）

```
偏差x = 目标中心x - 屏幕中心x
偏差y = 目标中心y - 屏幕中心y
```

例：目标中心 (1238,744) → 偏差 = (-42, +24)
意思是：目标在屏幕中心**左边 42 像素**、**下方 24 像素**。

### 第三步：变成鼠标移动方向

鼠标要往左上方移动：
- 偏差 x 为负 → 鼠标往左
- 偏差 y 为正 → 鼠标往下

## 为什么要做"坐标变换"而不直接用像素？

因为像素偏差 ≠ 鼠标移动量，中间要考虑：

1. **缩放**：模型看到的是缩小的图，要映射回原图
2. **FOV（视野）**：屏幕边缘的 10 像素和中心的 10 像素，鼠标需要的移动不一样
3. **轴比例**：x 和 y 方向可能需要不同的灵敏度
4. **控制量**：偏差 → PID → 平滑的移动量（不是生硬地跳过去）

## 真实数据流

```
检测框 (x1,y1,x2,y2)
   ↓ 中心点
目标中心 (cx, cy)
   ↓ 减屏幕中心
偏差 (error_x, error_y)
   ↓ PID 控制
鼠标移动量 (dx, dy)  ← 交给输出层（当前关闭）
```

## 常见问题

| 现象 | 原因 |
|---|---|
| 鼠标打偏 | 轴比例/灵敏度设置不对 |
| 框中心与目标中心有偏差 | 目标点可能按配置偏移（不一定是框中心）|
| 坐标乱跳 | 目标选择不稳定（多帧稳定机制未生效）|
