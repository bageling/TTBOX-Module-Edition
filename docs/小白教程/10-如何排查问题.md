# 10 - 如何排查问题？

> 遇到问题别慌，按顺序排查。
> 本文档给出最常见的排查路径，每一步都告诉你"怎么看、看什么"。

## 排查总原则

**从上到下、一层一层查**：
画面 → 采集 → 预处理 → 推理 → 解码 → 检测 → 选择 → 坐标 → 输出

哪一层出问题，就只看那一层，别乱改。

---

## 问题一：完全没有检测结果

按这个顺序查：

```
① 画面进来了吗？
   停服务 → v4l2-ctl 抓帧 → 看帧内容
   （全黑 = 信号问题；有内容 = 继续查）

② 模型加载了吗？
   journalctl -u ttbox-core.service | grep rknn_init
   （没有加载日志 = 模型路径错）

③ 模型输入格式对吗？
   ⚠ 最常见原因！FP16 模型必须喂原始 0~255 像素
   看 docs/AI/模型输入格式.md

④ 置信度阈值太低了吗？
   把 conf 调低一点试试（如 0.30）

⑤ 画面上有模型认识的目标吗？
   COCO 模型认人/车/公交；纯桌面图标它可能不认识
```

## 问题二：画面全黑/无信号

```
① HDMI 线插好了吗？（电脑显卡口 ↔ 盒子 HDMI RX 口）
② 虚拟显示器启用了吗？（GameViewer 驱动状态）
③ 板端信号锁定吗？
   hdmirx_edid --status
   （应显示 LOCK 2560×1440@144Hz）
④ 分辨率对吗？EDID 配置有没有生效？
```

## 问题三：检测框位置不对

```
① 坐标映射正确吗？
   运行 core/tests/test_decode_coords.cpp（应全 PASS 误差 0）
② ROI 配置对吗？（crop 500×500 是否居中）
③ 目标点偏移配置对吗？（aim point profile）
```

## 问题四：性能慢（帧率低）

```
① 模型太大？（640 vs 256 差 8.6 倍）
② 3 个 Worker 都启动了吗？（3 个 NPU 核）
③ 采集 FPS 正常吗？（应 141+）
   GET_STATUS 看 capture_fps
④ CPU 被占满？NPU 频率正常？
```

## 问题五：服务起不来

```
① 看日志：
   journalctl -u ttbox-core.service -n 50 --no-pager
② 常见原因：
   - 视频设备被占用（先停别的进程）
   - 模型路径错
   - 配置文件 JSON 语法错
   - HDMI 没锁定（会后台重试）
③ 恢复：
   systemctl restart ttbox-core.service
   systemctl status ttbox-core.service
```

## 问题六：Web 页面打不开

```
① ttbox-web 服务在吗？ systemctl status ttbox-web.service
② IPC socket 在吗？ ls -la /tmp/ttbox_core.sock
③ 端口占用？
```

## 检查工具一览

| 工具 | 用法 | 看什么 |
|---|---|---|
| `journalctl -u ttbox-core.service` | 板端 | 启动/模型/错误日志 |
| `ipc_ping --type GET_STATUS` | 板端 | 全部实时指标 |
| `v4l2-ctl -d /dev/video0 --all` | 板端 | 视频设备状态 |
| `hdmirx_edid --status` | 板端 | HDMI 信号/EDID |
| `imgdetect` | 板端 | 单张图片检测（验证模型/画面）|
| `fullscreen_*.py` | PC 端 | 生成测试画面 |
| `yolo_probe` | 板端 | 查询模型元数据 |

## 安全提醒（永远记住）

- 排查问题时 **output_enabled 必须保持 false**
- 不要为了"看看能不能动"开启鼠标注入
- 改代码前先备份（cp 文件 .bak-时间戳）
- 已验证的链路（HDMI/Capture/DecodeNMS 坐标）不要随意改
