# 问题排查

> 本文档是"遇到问题怎么办"的速查手册。按层排查，从上到下，哪层出问题只看哪层。

## 排查总原则

**从上到下、一层一层查**：

```
画面 → 采集 → 预处理 → 推理 → 解码 → 检测 → 选择 → 坐标 → 控制 → 输出
```

哪一层出问题，就只看那一层，别乱改。

## 问题一：完全没有检测结果

按这个顺序查：

```
① 画面进来了吗？
   停服务 → v4l2-ctl 抓帧 → 看帧内容
   （全黑 = 信号问题；有内容 = 继续查）

② 模型加载了吗？
   journalctl -u ttbox-core.service | grep rknn_init
   （没有加载日志 = 模型路径错）

③ 模型输入格式对吗？
   ⚠ 最常见原因！FP16 模型必须喂原始 0~255 像素
   看 docs/AI/模型输入格式.md

④ 置信度阈值太低了吗？
   把 conf 调低一点试试（如 0.30）

⑤ 画面上有模型认识的目标吗？
   COCO 模型认人/车/公交；纯桌面图标它可能不认识
```

## 问题二：画面全黑/无信号

```
① HDMI 线插好了吗？（电脑显卡口 ↔ 盒子 HDMI RX 口）
② 虚拟显示器启用了吗？（GameViewer 驱动状态）
③ 板端信号锁定吗？ hdmirx_edid --status
   （应显示 LOCK 2560×1440@144Hz）
④ 分辨率对吗？EDID 配置有没有生效？
```

## 问题三：有检测但 TargetSelector 没选到目标

```
① pipeline_debug 看 Detector: detections=N
   N=0 → 检测层问题（看问题一）
   N>0 但 Target: valid=0 → 选择层问题（继续查）
② TargetSelectorConfig 检查：
   - confidence 阈值是否太高（过滤了所有检测）
   - class_filter 是否过滤了目标类别
   - fov_range 是否太小（目标在搜索半径外）
③ 用 test_selector_stress 验证选择算法本身正常
```

## 问题四：Target 有但 TargetPoint/误差不对

```
① pipeline_debug 看 TargetPoint 值：
   - TargetPoint x/y 是否在原图范围内（0~2560 / 0~1440）
   - 越界/NaN → 坐标层异常
② AimPointProfile 检查：
   - offset_x/offset_y（框内瞄准点比例）
   - aim_offset_x/aim_offset_y（准星偏移）
③ 用 test_pipeline 测试7（坐标转换）验证数学正确
```

## 问题五：MouseCommand 异常

```
① pipeline_debug 看 Controller 行：
   - error 巨大 → 坐标层问题（看问题四）
   - dx/dy 巨大 → PID/输出链问题
② PidControllerParams 检查：
   - kp 是否过大（输出爆炸）
   - output_deadzone 是否合理
   - smooth 是否过小（9900≈不过滤）
③ 用 test_pipeline 测试8/9（Controller 单测）验证
```

## 问题六：服务起不来

```
① 看日志：
   journalctl -u ttbox-core.service -n 50 --no-pager
② 常见原因：
   - 视频设备被占用（先停别的进程）
   - 模型路径错
   - 配置文件 JSON 语法错
   - HDMI 没锁定（会后台重试）
③ 恢复：
   systemctl restart ttbox-core.service
   systemctl status ttbox-core.service
```

## 问题七：性能慢（帧率低）

```
① 模型太大？（640 vs 256 差 8.6 倍）
② 3 个 Worker 都启动了吗？（3 个 NPU 核）
③ 采集 FPS 正常吗？（应 140+） GET_STATUS 看 capture_fps
④ 板子热吗？ cat /sys/class/thermal/thermal_zone0/temp
   （>80°C 会降频，影响推理速度）
⑤ CPU 被占满？ top / uptime 看 load
```

## 问题八：日志刷屏/性能影响

```
① pipeline_debug 是否开启了？
   关闭：config 里 pipeline_debug_enabled=false
② 采样频率太高？
   pipeline_debug_interval 调大（默认 60）
③ 正常状态：每 60 帧输出一次（约 1 秒一次），不影响实时链路
```

## 问题九：安全状态怀疑被改

```
① 检查 config：output_enabled 必须 false
② 检查实时状态：GET_STATUS 的 injection_allowed 必须 false
③ 检查鼠标：mouse_dx/mouse_dy 必须 0
④ 如果发现被改：立即恢复 false + 重启服务 + 上报
```

## 检查工具一览

| 工具 | 用法 | 看什么 |
|---|---|---|
| `journalctl -u ttbox-core.service` | 板端 | 启动/模型/错误日志 + PIPELINE 诊断 |
| `ipc_ping --type GET_STATUS` | 板端 | 全部实时指标（帧率/检测/注入状态） |
| `v4l2-ctl -d /dev/video0 --all` | 板端 | 视频设备状态 |
| `hdmirx_edid --status` | 板端 | HDMI 信号/EDID |
| `imgdetect` | 板端 | 单张图片检测（验证模型/画面） |
| `fullscreen_*.py` | PC 端 | 生成测试画面 |
| `test_pipeline` | 双端 | Pipeline 10 项单元测试 |
| `pipeline_bench` | 双端 | 模块分项耗时基准 |

## 安全提醒（永远记住）

- 排查问题时 **output_enabled 必须保持 false**
- 不要为了"看看能不能动"开启鼠标注入
- 改代码前先备份（cp 文件 .bak-时间戳）
- 已验证的链路（HDMI/Capture/DecodeNMS 坐标）不要随意改
