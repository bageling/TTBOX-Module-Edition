## 2. Core（C++ 核心）结构

`core/src/` 下按功能划分子目录，全部为 C++ 源码：

| 目录 | 职责 | 关键文件 |
|---|---|---|
| `capture/` | 视频采集（V4L2 + DMA-BUF） | V4L2Capture.cpp/.hpp |
| `rga/` | RGA 硬件图像处理 | RgaProcessor.cpp/.hpp |
| `rknn/` | RKNN 推理 + 预处理 + 解码 | RKNNEngine / Preprocess / DecodeNMS / WorkerPool |
| `model/` | 模型适配与注册 | ModelAdapter / ModelRegistry / RuntimeProfile |
| `detector/` | 检测器接口 + 高性能引擎 | IDetector.hpp / HighPerfRknnEngine |
| `mouse/` | 目标选择 + 坐标 + 运动控制 | TargetSelector / CoordinateTransform / MouseTypes |
| `aim/` | 瞄准线程 + PID 控制 | AimThread / Pid1Controller |
| `output/` | 鼠标输出后端 | OutputBackend / FifoHidOutput / MakcuMouseBackend |
| `hid/` | HID 转发与解析 | HidForwarder / HidParser / HidRuntime |
| `input/` | 物理鼠标读取 | PhysicalMouseReader |
| `pipeline/` | 目标数据信箱（跨线程） | AimTargetMailbox |
| `preview/` | 预览模块（低帧率 JPEG） | PreviewModule |
| `ipc/` | IPC 服务（Web 控制接口） | IpcServer |
| `runtime/` | 运行时组装与调度 | CoreRuntime / HardwareRunner |
| `app/` | 应用主类 | Application |
| `config/` | 配置管理 | ConfigManager |
| `common/` | 公共工具 | Logger / Json / Stats / Types |
| `auth/` | 授权校验 | LicenseDaemon / DeviceFingerprint |
| `bench/` | 性能基准 | npu_bench |

## 3. 当前核心调用链（真实链路）

```
main.cpp
  → Application（配置/IPC/授权/启动）
    → CoreRuntime（组装）
      → V4L2Capture（/dev/video0 采集帧）
        → LatestFrame（最新帧缓存）
          → WorkerPool × 3 Worker（3 个 NPU 核）
            → Preprocess/RGA（裁剪 500×500 → 模型尺寸）
              → RKNNEngine（NPU 推理）
                → DecodeNMS（解码 + NMS → 原图坐标 Detection）
                  → AimTargetMailbox（目标数据）
                    → AimThread（选择目标 + PID 控制）
                      → OutputBackend → HID 输出（当前关闭）
```

## 4. Framework / Platform / Plugin 结构

### Framework（Python 框架层）
- `plugin_manager/`：插件发现、安装、完整性校验、生命周期、仓库、标准、事务
- `config/service.py`：配置服务
- `service/manager.py`：服务管理
- `security/policy.py`：安全策略
- `runtime.py`：运行时入口

### Platform（板端运维层）
- `supervisor/`：systemd 服务管理（runner.py / supervisor.py / systemd_units.py）
- `runtime/`：运行时控制器（controller.py / lifecycle.py / process_adapter.py）
- `model/`：模型生命周期与注册
- `health/`：健康检查
- `config/`：配置分层
- `update/`：升级组件

### Plugins（功能插件，12 个）
`fan / wifi / network / monitor / system / log / upgrade / web / preview / model`
每个插件含 `plugin.json`（声明）+ `plugin_entry.py`（入口）。
`web/` 还包含 `framework_api.py`（框架 API）与插件市场预留。
`preview/` 含 `preview_contract.py`（预览契约）。
`model/` 含 `model_service.py` / `model_contract.py`（模型服务契约）。

## 13. 当前存在的问题

1. **模型输入格式（已修复）**：FP16 模型被错误 /255 归一化导致"失明"，
   已改喂 UINT8 原始像素修复（见 docs/AI/模型输入格式.md）
2. **yolo261n 性能**：640×640 推理 63.5ms（43 FPS），
   比 jwdl 256×256（7.3ms/142FPS）慢约 8.6 倍，属 COCO 通用模型正常水平
3. **config.model_path 需显式指定**：默认会指向 installed/jwdl_sjzv11，切换模型易遗漏
4. **桌面无 COCO 目标时 detect=0**：模型正确拒识，测试需用 COCO 内容画面
5. **真实鼠标注入未做端到端验证**：当前保持 output_enabled=false（安全红线）

## 14. 敏感信息与不变量（必须永远遵守）

- `output_enabled=false`：禁止开启鼠标注入
- `injection_allowed=false`：禁止注入
- 板端 SSH 凭据、License 密钥、私钥：**永不入库**
- HDMI RX / EDID / Capture 架构 / DecodeNMS 坐标算法：已验证，禁止随意改动
- 桌面副本与板端源码需保持一致（板端可增量编译）
