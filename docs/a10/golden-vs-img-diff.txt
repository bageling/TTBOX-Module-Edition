================================================================
1. ROOT UUID（致命差异 = ROOT CAUSE）
================================================================
GOLDEN rootfs UUID  : c3855003-b298-4ef0-bb40-149bed57fd8c
IMG   rootfs UUID   : b782e19b-2294-4d60-b4f2-b5e0e493029e  ← mkfs.ext4 新生成

IMG 内 /boot/extlinux/extlinux.conf :
    append root=UUID=c3855003-b298-4ef0-bb40-149bed57fd8c ...   ← 旧 UUID（错）
IMG 内 /etc/fstab :
    UUID=c3855003-b298-4ef0-bb40-149bed57fd8c / ext4 ...        ← 旧 UUID（错）

→ 内核以 root=UUID=c3855003 查找分区，但新 rootfs 实际为 b782e19b
→ 根分区无法挂载，系统无法启动（initramfs 等待 root 超时）
→ 无 DRM 初始化、无任何显示输出（第一/第二屏均无）

修复：构建时 mkfs 后读取新 UUID，sed 更新 extlinux.conf + fstab（见 a10_build_v2.sh）

================================================================
10. 制作过程回溯（导致 UUID 差异的步骤）
================================================================
构建脚本 a10_build_rootfs.sh 流程：
  mkfs.ext4 → mount → rsync rootfs → 清理 → chroot 设账号 → umount
缺失步骤：mkfs 后未读取新 UUID、未更新 extlinux.conf / fstab
→ 这是唯一的制作缺陷；GOLDEN Boot/Kernel/DT 均被正确复制
